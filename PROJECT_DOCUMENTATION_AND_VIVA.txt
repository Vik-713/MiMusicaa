   Working:

10. controllers/playlistController.js

                    SECTION 2: VIVA QUESTIONS - NODE.JS & EXPRESS.JS

Q1. What is Node.js and why is it used?
A: Node.js is a JavaScript runtime built on Chrome's V8 engine that allows JavaScript to run on the server-side. It's used for building scalable network applications, APIs, and real-time applications due to its non-blocking, event-driven architecture.

Q2. What is Express.js?
A: Express.js is a minimal and flexible Node.js web application framework that provides a robust set of features for web and mobile applications. It simplifies routing, middleware integration, and HTTP request handling.

Q3. How does the MiMusicaa backend handle CORS?
A: The backend uses the 'cors' middleware configured to allow requests from localhost:5173 (frontend), with specific methods (GET, POST, PUT, PATCH, DELETE) and headers (Content-Type, Authorization) allowed.

Q4. What is middleware in Express.js?
A: Middleware are functions that have access to the request object (req), response object (res), and the next middleware function. They can execute code, modify req/res objects, end request-response cycle, or call next middleware.

Q5. Explain the authentication middleware in MiMusicaa.
A: The auth middleware extracts JWT token from Authorization header, verifies it using JWT_SECRET, and attaches the decoded user to req.user. It returns 401 if token is invalid or missing.

Q6. What is the difference between auth and optionalAuth middleware?
A: auth middleware requires a valid token and returns 401 if missing/invalid. optionalAuth attaches user if token exists but continues without error if token is missing, enabling guest browsing.

Q7. How does JWT authentication work in MiMusicaa?
A: During login/register, server generates JWT token with user ID payload, signs it with JWT_SECRET, and sends to client. Client stores token and sends it in Authorization header for protected routes.

Q8. What is bcryptjs and why is it used?
A: bcryptjs is a library for hashing passwords. It's used to securely store passwords by creating one-way hashes with salt, making it computationally expensive to reverse-engineer the original password.

Q9. How are passwords hashed in the User model?
A: A pre-save hook checks if password is modified, then hashes it using bcrypt.hash with salt rounds of 10 before saving to database. This ensures passwords are never stored in plain text.

Q10. What is Mongoose and its purpose?
A: Mongoose is an Object Data Modeling (ODM) library for MongoDB and Node.js. It provides schema-based solution to model application data, built-in validation, query building, and business logic hooks.

Q11. Explain the User schema in MiMusicaa.
A: User schema includes username, email, password (required, unique), and arrays for likedTracks, playlists, and queue (ObjectId references). It has pre-save hook for password hashing and comparePassword method.

Q12. What are Mongoose schema references?
A: References allow linking documents across collections using ObjectId. In MiMusicaa, User references Track and Playlist collections, enabling population of related data when querying.

Q13. What is the populate() method in Mongoose?
A: populate() replaces ObjectId references with actual documents from referenced collections. For example, User.populate('likedTracks') replaces track IDs with full track objects.

Q14. How does the Track model differ from User model?
A: Track model doesn't have user reference as tracks are static seed data. It includes genre, duration, album fields for categorization, and playCount for analytics.

Q15. What is the purpose of timestamps in Mongoose schemas?
A: timestamps: true automatically adds createdAt and updatedAt fields to documents, tracking when documents are created and last modified.

Q16. Explain the PlayHistory model's purpose.
A: PlayHistory tracks when users play tracks by storing user ID, track ID, and playedAt timestamp. It has an index on user and playedAt for efficient querying of recently played tracks.

Q17. What are Mongoose indexes and why use them?
A: Indexes improve query performance by creating data structures that allow faster lookups. PlayHistory uses compound index on user and playedAt for efficient recent tracks queries.

Q18. How does the seed script work?
A: seed.js connects to MongoDB, clears existing tracks, inserts 30 sample tracks with metadata, and exits. It's run via "npm run seed" to populate database with demo data.

Q19. What is the purpose of dotenv package?
A: dotenv loads environment variables from .env file into process.env, keeping sensitive data (database URLs, secrets) separate from code and version control.

Q20. How does MiMusicaa implement audio streaming?
A: streamTrack controller uses fs.createReadStream to stream audio files with HTTP range request support, sending 206 Partial Content responses for seek functionality.

Q21. What are HTTP range requests?
A: Range requests allow clients to request specific byte ranges of a file. The server responds with 206 status and Content-Range header, enabling video/audio seeking without re-downloading entire file.

Q22. Explain the like/unlike track functionality.
A: likeTrack adds track ID to user's likedTracks array using push(). unlikeTrack filters the array to remove the track ID. Both save the updated user document.

Q23. How does play count increment work?
A: incrementPlayCount uses findByIdAndUpdate with $inc operator to atomically increment playCount by 1. If user is authenticated, it also creates PlayHistory entry.

Q24. What is the $inc operator in MongoDB?
A: $inc is an update operator that increments a field's value by specified amount. It's atomic and efficient for counters like playCount.

Q25. How are recently played tracks retrieved?
A: getRecentlyPlayed queries PlayHistory for user's entries, sorts by playedAt descending, limits to 20, populates track data, and filters for unique tracks.

Q26. Explain playlist creation process.
A: createPlaylist creates new Playlist document with user ID, then adds playlist ID to user's playlists array and saves both documents.

Q27. How does authorization work for playlists?
A: Controllers check if playlist.user matches req.user.id. If not, they return 403 Forbidden status, preventing users from modifying others' playlists.

Q28. What is the purpose of Express Router?
A: Router creates modular, mountable route handlers. MiMusicaa uses separate routers for auth, tracks, playlists, and queue, keeping code organized.

Q29. How does the queue management work?
A: Queue is stored as array of track IDs in User model. Controllers provide methods to get, update (replace), add, remove, and clear the queue array.

Q30. What is the difference between PUT and PATCH?
A: PUT replaces entire resource (updateQueue replaces whole queue array). PATCH partially updates resource (updatePlaylist only modifies specified fields).

Q31. How does error handling work in controllers?
A: Controllers use try-catch blocks to catch errors, log them to console, and return appropriate HTTP status codes (400, 401, 403, 404, 500) with error messages.

Q32. What HTTP status codes are used in MiMusicaa?
A: 200 (OK), 201 (Created), 206 (Partial Content), 400 (Bad Request), 401 (Unauthorized), 403 (Forbidden), 404 (Not Found), 500 (Server Error).

Q33. What is the purpose of express.json() middleware?
A: express.json() parses incoming requests with JSON payloads and makes the parsed data available in req.body.

Q34. How does static file serving work?
A: express.static('uploads') middleware serves files from uploads directory, making audio files and images accessible via HTTP URLs.

Q35. What is nodemon and its benefit?
A: nodemon is a development tool that automatically restarts Node.js application when file changes are detected, improving development workflow.

Q36. Explain the register controller function.
A: register checks if user exists, creates new User with hashed password, generates JWT token with user ID, and returns token with user data (excluding password).

Q37. How does login authentication work?
A: login finds user by email, uses comparePassword method to verify password hash, generates JWT token if valid, and returns token with user data.

Q38. What is the getMe controller used for?
A: getMe retrieves authenticated user's profile using req.user.id, populates likedTracks, playlists, and queue, excludes password, and returns complete user data.

Q39. How does search functionality work in getTracks?
A: getTracks uses $or operator with $regex for case-insensitive search across title, artist, and album fields, combined with optional genre filter.

Q40. What is the $or operator in MongoDB?
A: $or performs logical OR operation on array of query expressions, returning documents that match at least one condition.

Q41. What is $regex in MongoDB queries?
A: $regex provides regular expression pattern matching in queries. With 'i' option, it performs case-insensitive searches.

Q42. How does genre filtering work?
A: getTracks checks if genre query parameter exists, adds it to MongoDB query object, and returns only tracks matching that genre.

Q43. Explain the file streaming implementation.
A: streamTrack gets file stats, parses range header, creates read stream with start/end bytes, sets appropriate headers (Content-Range, Content-Length), and pipes stream to response.

Q44. What is fs.createReadStream?
A: createReadStream creates a readable stream for file content, allowing efficient reading of large files in chunks without loading entire file into memory.

Q45. How does the playlist update work?
A: updatePlaylist finds playlist, checks ownership, updates only provided fields (name, description, coverImage), saves document, and returns updated playlist.

Q46. What is the purpose of findByIdAndUpdate?
A: findByIdAndUpdate finds document by ID, applies updates, and returns updated document. With {new: true}, it returns the modified document instead of original.

Q47. How are tracks added to playlists?
A: addTrackToPlaylist checks if track already exists in playlist.tracks array, pushes track ID if not, saves playlist, and returns populated playlist with track details.

Q48. Explain the removeTrackFromPlaylist function.
A: It filters playlist.tracks array to exclude the specified track ID, saves the updated playlist, and returns the playlist with populated track data.

Q49. How does queue clearing work?
A: clearQueue sets user.queue to empty array, saves user document, and returns success message with empty queue.

Q50. What is the role of async/await in controllers?
A: async/await provides cleaner syntax for handling asynchronous operations (database queries, file operations), making code more readable and easier to debug than callbacks or raw promises.

Q1. What is React and why is it used?
A: React is a JavaScript library for building user interfaces, particularly single-page applications. It's used for creating reusable UI components, efficient DOM updates via virtual DOM, and managing complex application state.

Q2. What is JSX?
A: JSX (JavaScript XML) is a syntax extension that allows writing HTML-like code in JavaScript. It's transpiled to React.createElement calls and makes component structure more readable.

Q3. What are React components?
A: Components are independent, reusable pieces of UI that accept inputs (props) and return React elements. They can be functional (using hooks) or class-based.

Q4. What is the difference between functional and class components?
A: Functional components are JavaScript functions that return JSX, using hooks for state and lifecycle. Class components use ES6 classes with render method and lifecycle methods. Modern React favors functional components.

Q5. What are React Hooks?
A: Hooks are functions that let you use state and lifecycle features in functional components. Common hooks include useState, useEffect, useContext, useRef, etc.

Q6. Explain useState hook with MiMusicaa example.
A: useState manages component state. In Search.jsx, useState('') creates searchQuery state and setSearchQuery updater. When user types, setSearchQuery updates state and triggers re-render.

Q7. What is useEffect hook?
A: useEffect performs side effects in functional components (data fetching, subscriptions, DOM manipulation). It runs after render and can clean up with return function.

Q8. How does useEffect work in Home.jsx?
A: useEffect with empty dependency array [] runs once on mount, fetching tracks and recently played data. It's equivalent to componentDidMount in class components.

Q9. What are useEffect dependencies?
A: Dependencies array controls when effect runs. Empty [] runs once on mount. [searchQuery] runs when searchQuery changes. No array runs after every render.

Q10. Explain useContext hook in MiMusicaa.
A: useContext accesses context values without prop drilling. useAuth() hook uses useContext(AuthContext) to access user, login, logout functions throughout app.

Q11. What is React Context API?
A: Context provides way to pass data through component tree without passing props manually at every level. MiMusicaa uses AuthContext and PlayerContext.

Q12. How does AuthContext work?
A: AuthContext provides user state, login, logout, and modal control. App.jsx creates context with useState for user and functions. Components access via useAuth() hook.

Q13. Explain PlayerContext implementation.
A: PlayerContext manages global audio state (currentTrack, isPlaying, queue). It creates Audio element, provides playback controls, and shares state across components via usePlayer() hook.

Q14. What is useRef hook?
A: useRef creates mutable reference that persists across renders. PlayerContext uses audioRef to reference Audio element without causing re-renders on changes.

Q15. How does the audio player work in PlayerContext?
A: PlayerContext creates Audio element via useRef, sets src to stream URL, attaches event listeners (timeupdate, ended), and provides control functions (play, pause, seek).

Q16. What are React event listeners?
A: Event listeners respond to user interactions. MiMusicaa uses onClick, onChange, onSubmit. They receive synthetic events and call handler functions.

Q17. How does debouncing work in Search.jsx?
A: useEffect with setTimeout delays API call by 500ms after user stops typing. clearTimeout in cleanup function cancels previous timeout, preventing excessive API calls.

Q18. What is the purpose of cleanup in useEffect?
A: Cleanup function (returned from useEffect) runs before effect re-runs or component unmounts. It's used to cancel subscriptions, clear timers, remove event listeners.

Q19. Explain React Router in MiMusicaa.
A: React Router provides client-side routing. BrowserRouter wraps app, Routes defines route matching, Route maps paths to components, Link/useNavigate handle navigation.

Q20. What is the difference between Link and useNavigate?
A: Link is a component for declarative navigation (renders anchor tag). useNavigate is a hook for programmatic navigation (navigate(-1) for back, navigate('/path') for specific route).

Q21. How does route highlighting work in Sidebar?
A: useLocation hook gets current pathname. isActive function compares pathname with route path. Active route gets green background, others get gray.

Q22. What are props in React?
A: Props (properties) are read-only inputs passed from parent to child components. MusicCard receives track prop from Home.jsx to display track data.

Q23. How does prop drilling work?
A: Prop drilling passes props through intermediate components to reach deeply nested child. Context API solves this by providing direct access to shared state.

Q24. What is component composition?
A: Composition builds complex UIs from smaller components. Home.jsx composes multiple MusicCard components in grid layout, passing different track data to each.

Q25. Explain conditional rendering in MiMusicaa.
A: Components use ternary operators and && for conditional rendering. PlayerBar shows "No track playing" when !currentTrack. Library shows empty state when likedTracks.length === 0.

Q26. What is the map() function in React?
A: map() transforms array into array of JSX elements. Home.jsx uses tracks.map(track => <MusicCard key={track._id} track={track} />) to render track cards.

Q27. Why are keys important in lists?
A: Keys help React identify which items changed, added, or removed. They should be stable, unique identifiers (like _id) to optimize re-rendering.

Q28. How does form handling work in App.jsx?
A: Login form uses document.getElementById to get input values, sends data via axios.post, handles success (login, close modal) and errors (alert message).

Q29. What is controlled vs uncontrolled components?
A: Controlled components have React state controlling input value (value={searchQuery} onChange={e => setSearchQuery(e.target.value)}). Uncontrolled use refs or DOM directly.

Q30. How does the search input work in Search.jsx?
A: Search input is controlled component with value={searchQuery} and onChange={e => setSearchQuery(e.target.value)}. State updates trigger debounced API call.

Q31. Explain onClick event handling in MusicCard.
A: onClick={handlePlay} on card calls playTrack from PlayerContext. e.stopPropagation() on like button prevents card click when clicking like.

Q32. What is event bubbling?
A: Events propagate from target element up through ancestors. stopPropagation() prevents this, so clicking like button doesn't trigger card's onClick.

Q33. How does the like button work in MusicCard?
A: handleLike checks if user exists (alert if not), calls trackAPI.likeTrack or unlikeTrack based on isLiked state, updates state on success.

Q34. What is async/await in React?
A: async/await handles asynchronous operations (API calls) in cleaner syntax. handleLike is async function, awaits trackAPI calls, handles errors in catch block.

Q35. How does axios work in MiMusicaa?
A: axios is HTTP client. api.js creates instance with baseURL, request interceptor adds token. Components import trackAPI, playlistAPI methods for API calls.

Q36. What are axios interceptors?
A: Interceptors modify requests/responses globally. Request interceptor in api.js reads token from localStorage and adds to Authorization header for all requests.

Q37. How does token persistence work?
A: login function saves token and user to localStorage. On app load, useEffect reads token, sets axios header. logout removes from localStorage.

Q38. Explain the player controls in PlayerBar.
A: PlayerBar uses PlayerContext functions: togglePlay for play/pause, playNext/playPrevious for navigation, seekTo for progress bar clicks, setVolume for volume slider.

Q39. How does the progress bar work?
A: Progress bar calculates percentage (currentTime/duration * 100), displays as width. onClick gets click position, calculates percentage, calls seekTo with new time.

Q40. What is the purpose of formatTime function?
A: formatTime converts seconds to MM:SS format for display. It calculates minutes (Math.floor(seconds/60)) and seconds (seconds % 60), padding with zeros.

Q41. How does the volume slider work?
A: Range input with value={volume} and onChange={e => setVolume(parseFloat(e.target.value))}. PlayerContext's useEffect updates audioRef.current.volume when volume state changes.

Q42. Explain the play button overlay in MusicCard.
A: CSS classes use group and group-hover. Play button has opacity-0 group-hover:opacity-100, making it visible only when hovering over card.

Q43. What are Tailwind CSS utility classes?
A: Tailwind provides pre-built CSS classes for styling. bg-zinc-900 sets background, text-white sets color, rounded-lg adds border radius, flex enables flexbox.

Q44. How does responsive design work in MiMusicaa?
A: Tailwind's responsive prefixes (md:, lg:, xl:) apply styles at breakpoints. grid-cols-2 md:grid-cols-3 lg:grid-cols-4 adjusts columns based on screen size.

Q45. What is the purpose of className in React?
A: className sets CSS classes on elements (equivalent to HTML's class). React uses className to avoid conflict with JavaScript's class keyword.

Q46. How does the genre filter work in Search.jsx?
A: Genre buttons call setSelectedGenre(genre) onClick. useEffect watches selectedGenre, triggers fetchTracks when it changes, passing genre as query parameter.

Q47. Explain the loading state in Home.jsx.
A: useState(true) creates loading state. fetchTracks sets loading to false after API call. Component returns loading message if loading is true.

Q48. What is the purpose of try-catch in React?
A: try-catch handles errors in async operations. fetchTracks wraps API call in try, catches errors, logs them, and sets loading to false in finally.

Q49. How does navigation work in Library.jsx?
A: useNavigate hook creates navigate function. Clicking playlist card calls navigate(`/playlist/${playlist._id}`), routing to playlist detail page.

Q50. What is the virtual DOM in React?
A: Virtual DOM is lightweight copy of actual DOM. React compares virtual DOM snapshots (diffing), calculates minimal changes, and updates real DOM efficiently (reconciliation).

Q1. What is a full stack application?
A: A full stack application includes both frontend (client-side UI) and backend (server-side logic, database). MiMusicaa has React frontend and Node.js/Express backend.

Q2. How do frontend and backend communicate in MiMusicaa?
A: Frontend makes HTTP requests to backend API endpoints using axios. Backend processes requests, interacts with database, and sends JSON responses.

Q3. What is REST API?
A: REST (Representational State Transfer) is architectural style for APIs using HTTP methods (GET, POST, PUT, DELETE) and stateless communication. MiMusicaa follows RESTful principles.

Q4. Explain the authentication flow in MiMusicaa.
A: User submits credentials → Backend validates → Generates JWT token → Returns token to frontend → Frontend stores in localStorage → Includes token in subsequent requests → Backend verifies token.

Q5. What is JWT (JSON Web Token)?
A: JWT is compact, URL-safe token for transmitting information between parties. It contains header, payload (user data), and signature (verified with secret key).

Q6. How is JWT different from session-based authentication?
A: JWT is stateless (server doesn't store sessions), scalable, and works across domains. Session-based stores session data on server, requires cookies, harder to scale.

Q7. What is CORS and why is it needed?
A: CORS (Cross-Origin Resource Sharing) allows frontend (localhost:5173) to request resources from backend (localhost:5001) on different origin. Without CORS, browsers block cross-origin requests.

Q8. How does MiMusicaa handle CORS?
A: Backend uses cors middleware configured with origin: 'localhost:5173', specific methods, headers, and credentials: true to allow authenticated cross-origin requests.

Q9. What is the purpose of environment variables?
A: Environment variables store sensitive configuration (database URLs, secrets, API keys) outside code. They vary by environment (development, production) and aren't committed to version control.

Q10. How are environment variables used in MiMusicaa?
A: Backend uses dotenv to load .env file with MONGO_URI, JWT_SECRET, PORT. Frontend uses import.meta.env for Vite environment variables.

Q11. What is MongoDB and why use it?
A: MongoDB is NoSQL document database storing data in JSON-like format. It's flexible (schema-less), scalable, and works well with JavaScript (JSON native).

Q12. What is the difference between SQL and NoSQL?
A: SQL databases use structured tables with fixed schemas and relationships. NoSQL (like MongoDB) uses flexible documents, scales horizontally, and suits unstructured data.

Q13. How does data modeling work in MiMusicaa?
A: Mongoose schemas define data structure. User has arrays of ObjectId references to Track and Playlist. Playlist references Track. PlayHistory links User and Track.

Q14. What are database relationships in MiMusicaa?
A: One-to-many: User has many Playlists, Playlists have many Tracks. Many-to-many: Users can like many Tracks, Tracks can be liked by many Users (via likedTracks array).

Q15. How does data persistence work?
A: User-specific data (likes, playlists, queue, history) is stored in MongoDB. Track metadata is static seed data. Changes persist across sessions via database storage.

Q16. What is the purpose of seed data?
A: Seed data populates database with initial content for testing and demonstration. MiMusicaa's seed script adds 30 sample tracks so app has content without user uploads.

Q17. How does file storage work in MiMusicaa?
A: Audio files and cover images are stored in uploads/ directory on server filesystem. Database stores file paths. express.static serves files via HTTP URLs.

Q18. What is the difference between storing files in database vs filesystem?
A: Filesystem is efficient for large files (audio, images), faster access, easier to serve. Database is better for metadata, ensures ACID properties, but slower for large binaries.

Q19. How does audio streaming work end-to-end?
A: Frontend sets audio.src to stream URL → Browser requests with range header → Backend reads file chunk → Sends 206 response with partial content → Browser plays and seeks efficiently.

Q20. What are HTTP status codes and their meanings?
A: 2xx (success): 200 OK, 201 Created, 206 Partial Content. 4xx (client error): 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found. 5xx (server error): 500 Internal Server Error.

Q21. How does error handling work across stack?
A: Backend catches errors, returns appropriate status codes and messages. Frontend handles errors in catch blocks, displays user-friendly messages (alerts, error states).

Q22. What is API versioning and why is it important?
A: API versioning (/api/v1/tracks) allows breaking changes without affecting existing clients. MiMusicaa doesn't version yet but could add /api/v2 for future changes.

Q23. How does state management work in full stack app?
A: Backend manages persistent state in database. Frontend manages UI state (React state, Context). They sync via API calls (fetch on mount, update on user action).

Q24. What is optimistic vs pessimistic updating?
A: Optimistic updates UI immediately, reverts on error (faster UX). Pessimistic waits for server confirmation (more reliable). MiMusicaa uses pessimistic (waits for API response).

Q25. How does real-time communication work?
A: MiMusicaa doesn't use real-time, but could add WebSockets or Server-Sent Events for live updates (new tracks, collaborative playlists, currently playing for friends).

Q26. What is the purpose of middleware in full stack?
A: Backend middleware processes requests (authentication, logging, parsing). Frontend doesn't have traditional middleware but uses axios interceptors for similar purpose.

Q27. How does routing work in full stack app?
A: Backend routes map HTTP methods and paths to controllers. Frontend routes map URLs to components. They're independent - backend serves API, frontend handles UI navigation.

Q28. What is SPA (Single Page Application)?
A: SPA loads single HTML page, dynamically updates content via JavaScript. MiMusicaa frontend is SPA - React Router changes views without page reloads.

Q29. How does client-side routing work?
A: React Router intercepts link clicks, updates URL with History API, matches route, renders component - all without server request. Browser back/forward buttons work via history.

Q30. What is the difference between server-side and client-side rendering?
A: Server-side renders HTML on server, sends complete page. Client-side (MiMusicaa) sends minimal HTML, JavaScript renders UI in browser. CSR is faster navigation, SSR is better SEO.

Q31. How does authentication state persist across page refreshes?
A: Token and user data stored in localStorage. On app load, useEffect reads localStorage, sets axios header, restores user state. Logout clears localStorage.

Q32. What is the purpose of axios interceptors in full stack context?
A: Request interceptor adds token to all API calls automatically. Response interceptor could handle token refresh, global error handling, or redirect on 401.

Q33. How does the like feature work end-to-end?
A: User clicks heart → Frontend calls trackAPI.likeTrack → Backend adds track to user.likedTracks → Saves to database → Returns success → Frontend updates UI state.

Q34. Explain the playlist creation flow.
A: User submits form → Frontend calls playlistAPI.createPlaylist → Backend creates Playlist document → Adds to user.playlists → Saves both → Returns playlist → Frontend updates library view.

Q35. How does search work across the stack?
A: User types → Debounced state update → Frontend calls getTracks with search param → Backend queries with $regex → Returns matching tracks → Frontend displays results.

Q36. What is API rate limiting and why use it?
A: Rate limiting restricts number of requests per time period to prevent abuse. MiMusicaa doesn't implement it but could add express-rate-limit for production.

Q37. How would you implement pagination in MiMusicaa?
A: Backend: Accept page and limit params, use skip() and limit() in query. Frontend: Add page state, next/prev buttons, update query params, fetch new page.

Q38. What is caching and how could it improve MiMusicaa?
A: Caching stores frequently accessed data in memory (Redis) or browser (localStorage). Could cache track list, user profile, reducing database queries and API calls.

Q39. How does the play history feature work?
A: User plays track → Frontend calls incrementPlayCount → Backend increments count → If authenticated, creates PlayHistory entry → Frontend fetches recent tracks → Displays in Home.

Q40. What is the purpose of database indexing?
A: Indexes speed up queries by creating data structures for fast lookups. PlayHistory has compound index on user and playedAt for efficient recent tracks queries.

Q41. How would you deploy MiMusicaa to production?
A: Backend: Deploy to Heroku/AWS/DigitalOcean, use MongoDB Atlas, set environment variables. Frontend: Build with npm run build, deploy to Netlify/Vercel, configure API URL.

Q42. What is the difference between development and production builds?
A: Development includes source maps, hot reload, verbose errors. Production is minified, optimized, removes console logs, uses environment-specific configs.

Q43. How does security work in MiMusicaa?
A: Password hashing (bcrypt), JWT authentication, CORS configuration, input validation, authorization checks (users can't modify others' playlists).

Q44. What are common security vulnerabilities in full stack apps?
A: SQL injection (use parameterized queries), XSS (sanitize input), CSRF (use tokens), insecure authentication (hash passwords), exposed secrets (use env variables).

Q45. How would you add user profile pictures to MiMusicaa?
A: Backend: Add multer middleware for file upload, store in uploads/avatars, save path in User model. Frontend: Add file input, send FormData, display image from URL.

Q46. What is the purpose of validation in full stack apps?
A: Frontend validation provides immediate feedback (required fields, email format). Backend validation ensures data integrity (can't trust client). Both are necessary.

Q47. How does the queue feature work end-to-end?
A: User adds track → Frontend calls queueAPI.addToQueue → Backend pushes to user.queue → Saves → Returns updated queue → PlayerContext updates state → Next track plays from queue.

Q48. What is the difference between authentication and authorization?
A: Authentication verifies identity (login with credentials). Authorization determines permissions (users can only modify their own playlists).

Q49. How would you implement playlist sharing in MiMusicaa?
A: Add public/private field to Playlist, generate shareable link, create public route (no auth), allow users to copy/import shared playlists.

Q50. What is the purpose of logging in production?
A: Logging tracks errors, user actions, performance metrics for debugging and monitoring. Could use Winston/Morgan for backend, Sentry for frontend error tracking.
